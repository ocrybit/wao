# Vibe Engineer's Guide to AO Development

Welcome to vibe engineering! This guide shows you how to build real applications on the AO hypercomputer by simply describing what you want. No coding experience required - just open [Claude Code](https://claude.ai/code) and start talking.

## What is Vibe Engineering?

Vibe engineering is building software by describing what you want in plain English. You tell Claude what to build, and it writes the code, runs the tests, and fixes any issues. Your job is to have ideas and give feedback.

## What You'll Build

By the end of this guide, you'll have created:
- **Counter** - A simple app that counts up and down
- **Token** - A cryptocurrency with transfers and minting
- **Messenger** - A chat system where processes talk to each other
- **Custom Devices** - Extend HyperBEAM with new capabilities

All running on AO's decentralized hypercomputer.

## Building Your First App: Counter

### What It Does

A counter that can:
- Show the current count
- Go up by 1
- Go down by 1
- Add any number
- Reset to zero

### How to Build It

Tell Claude:

```
Build me a counter app for AO.

It should:
- Start at 0
- Have handlers for: Get (show count), Inc (add 1), Dec (subtract 1), Add (add any number), Reset (back to 0)
- Return the new count after each operation

Write tests to make sure it all works, then run them.
```

Claude will create:
- `counter.lua` - The counter logic
- `counter.test.js` - Tests that verify everything works

### Try It Out

Once Claude says the tests pass, ask:

```
Show me how to manually test the counter.
Increment it 3 times, then add 100, then show me the count.
```

### Understanding What Claude Built

Ask Claude:

```
Explain the counter code to me like I'm a beginner.
What is a handler? What is state? How do messages work?
```

Key concepts you'll learn:
- **State** - The count that remembers its value
- **Handlers** - Functions that respond when you send actions
- **Messages** - How you talk to the app
- **Dryruns** - Checking the count without changing it

## Building a Token: Your Own Cryptocurrency

### What It Does

A real token with:
- Balances for each holder
- Transfers between people
- Minting (creating new tokens)
- Burning (destroying tokens)
- Allowances (letting others spend your tokens)

### How to Build It

Tell Claude:

```
Build me a token app that follows the ao Standard Token Specification.

It should have:
- Name: "My Token", Ticker: "MTK"
- Handlers for: Info, Balance, Balances, Transfer, Mint, Burn, Approve, Allowance, Transfer-From
- Only the owner can mint new tokens
- Transfers should send Debit-Notice and Credit-Notice to the parties involved

Use big integers for precise math.
Write comprehensive tests including:
- Minting tokens
- Transferring between accounts
- Checking balances
- Burning tokens
- Approving and using allowances

Run all the tests.
```

### Test the Token

After tests pass, try:

```
Walk me through a scenario:
1. Mint 1 million tokens to the owner
2. Transfer 10,000 to Alice
3. Alice approves Bob to spend 5,000
4. Bob transfers 2,500 from Alice to himself
5. Show me all the balances at the end
```

### Customize Your Token

Want changes? Just ask:

```
Change the token name to "Awesome Coin" with ticker "AWE".
Add a max supply of 100 million that can never be exceeded.
Run the tests again.
```

## Building a Messenger: Processes Talking to Each Other

### What It Does

A messaging system where:
- Each user has their own process
- Users can register with a name
- Add contacts (other processes)
- Send messages between processes
- Broadcast to all contacts
- Ping/pong to check if someone's online

### How to Build It

Tell Claude:

```
Build me a messenger app that demonstrates inter-process communication on AO.

It should have:
- Registration (set your display name)
- Contact management (add contacts, list them)
- Messaging (send to specific contact, receive messages)
- Inbox and outbox to track messages
- Broadcast (send to all contacts at once)
- Ping/Pong (check if a contact is responsive)

Use Send() for delivering messages to other processes via push@1.0.

Write tests with two processes (Alice and Bob) that:
- Both register with names
- Add each other as contacts
- Exchange messages
- Alice broadcasts to all contacts

Run all tests.
```

### Watch Processes Talk

Ask Claude:

```
Show me the message flow when Alice sends "Hello!" to Bob.
What happens step by step?
```

### The Magic of Inter-Process Communication

This is where AO gets powerful. Ask:

```
Explain how Send() and push@1.0 work.
How does a message get from Alice's process to Bob's process?
```

## Testing with HyperBEAM Beta3

So far we've tested in-memory (fast but simulated). Now let's test with real HyperBEAM.

### Why HyperBEAM?

- **In-memory tests** - Fast (milliseconds), great for development
- **HyperBEAM tests** - Real execution, proves it works in production

### Run HyperBEAM Tests

Tell Claude:

```
Create HyperBEAM tests for my counter app.
Start a local beta3 node, spawn a process, and test the counter operations.
```

Claude will create `counter.hyperbeam.test.js` that:
- Starts a local HyperBEAM node
- Spawns a real process with HTTP signatures
- Schedules messages through the beta3 protocol
- Verifies everything works

### Understanding Beta3

Ask Claude:

```
Explain HyperBEAM beta3 to me:
- What are devices?
- What is HTTP message signing?
- What are slots?
- How is this different from in-memory testing?
```

## Building Custom Devices

Devices extend what HyperBEAM can do. They're like plugins.

### Built-in Devices

Tell Claude:

```
Explain the main HyperBEAM devices:
- process@1.0
- scheduler@1.0
- push@1.0
- json-iface@1.0
- wasm-64@1.0

What does each one do?
```

### Device Composition

Devices stack together. Ask Claude:

```
Show me how device stacks work.
What's the difference between:
- A basic test process
- A full WASM AOS process with the mainnet device stack

Create examples of both.
```

### Creating Custom Behavior

Tell Claude:

```
I want to create a rate-limiter that:
- Tracks how many messages each sender has sent
- Rejects messages if someone sends more than 10 per minute

Build this as a Lua module I can add to my apps.
Write tests for it.
```

## Three Types of AOS Apps

Now you understand the three main patterns:

### 1. Stateful Apps (Counter)

Simple state that changes over time.

```
Build me an app that tracks a shopping cart.
Users can add items, remove items, and checkout.
```

### 2. Financial Apps (Token)

Complex state with validation and notifications.

```
Build me an NFT collection where:
- Each NFT has a unique ID and metadata
- Owners can transfer NFTs
- There's a minting limit of 1000
```

### 3. Communication Apps (Messenger)

Multiple processes working together.

```
Build me a voting system where:
- There's a main process for proposals
- Each voter has their own process
- Voters can submit votes that get tallied
- Results are broadcast when voting ends
```
